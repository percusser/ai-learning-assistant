What the learner assistant does

Every item here is a tool the assistant can call today.

Answers from your content
Searches the course content your organization has uploaded, first through saved Q&A pairs and then through vector search, and answers from what comes back. It is told to cite only what search returns.
Summaries that jump
Summarizes a course or module from stored content and links to the exact spot in the player.
Practice on demand
Builds a quiz, flashcards, matching, ordering, fill in the blank, a code challenge, a scenario, or a concept map on request. It builds one activity per turn.
Practice that picks itself
Asks which skills a learner is weakest on, then either serves a stored item or generates one at the right difficulty. It can also tell the learner to stop and shows where they stand.
Grading you can trust
Answers are graded on the server, and the answer keys are hidden from the stream, so the browser never holds the solution.
Explanations
Writes sectioned explanations with diagrams, and builds a throwaway visual explainer that runs sandboxed and is never graded.
Role play
Finds a scenario in your library, offers it, and starts a live voice call or text run inside the chat.
What to learn next
Recommends up to three items, and searches courses, paths, exams, and live events by topic.
Progress and study plans
Reports progress, deadlines, and mastery movement, and builds a session-by-session plan weighted to the weakest skills.
Enroll and launch
Checks eligibility, enrolls the learner or requests approval, and opens content. Enrolling needs the learner to approve it first.
Notes the learner controls
Proposes a note about goals or preferences. The learner approves each one, can see all of them, and can delete everything.
Adapts to the learner
The prompt carries the learner’s top 15 skills, grouped weak, developing, and strong, and the tone and depth change with them.

The admin assistant

A separate assistant for admins and managers, with its own tools and its own permissions.

Enrollments
Single and bulk enroll, due-date changes, and unenroll. Every write shows a preview and waits for a confirm.
Groups and users
Create groups, change members, search users including by custom field, and deactivate with confirmation.
Dashboards and reports
Plans and builds charts, saves, shares, exports, and answers org stats.
Approvals
An inbox of pending actions that can be approved or cancelled.
Background agents
Stalled enrollments, compliance gaps, a weekly digest, and a portfolio review. Each runs only where an org has chosen to opt in, with run history in the admin.
Out of scope requests
Get no write tools, a list of what the assistant can do, and a link to the right admin page.

The stack

How it is built, in the order a request travels.

Model
Google Gemini, streamed to the browser as it writes, with the reasoning optionally shown.
Retrieval
Embeddings and vector search in Postgres over course-linked materials, with a saved Q&A match tried first.
Rich answers
Cards and activities arrive as structured parts. Common ones are built into the app. Others use A2UI, an open format for model-driven UI, drawn only from a catalog we ship. A name outside the catalog falls back safely. One-off explainers run in a sandboxed frame.
Tools and permissions
Every tool is tagged safe or confirm and tied to a permission. The assistant only sees tools the person is permitted to use.
Confirm tier
A write waits for approval that is bound to the exact input, is single-use, and is checked again when it runs. Every approval, rejection, and block is recorded in an audit log.
Guardrails
A prompt-injection check turns off activity tools when it trips. Tool results are treated as data, not instructions. Answers are told to cite only what search returns.
Tenant isolation
Calls run as the learner, so database rules apply, and the tenant comes from the session, never from the request.
Access
Turned on per organization and per feature, and closed by default if the check fails.
